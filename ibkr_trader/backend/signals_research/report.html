Signals Model Trading-Edge Backtest

The Signals tab's live XGBoost BUY/SELL/HOLD classifier (AAPL/MSFT/NVDA/SPY) has been display-only since it was built and had never been tested as an actual trading rule. This asks the question honestly, across 2.5 years of real 5-min bars, before any execution code gets written.

Not starting from a blank page

The live model (main.py's build_features() / train_model() / predict()) turned out to have real, previously-unknown limitations: it's a single classifier shared across all 4 tickers rather than one per ticker, trained on just 5 days of 5-min bars, predicting next-5-min-bar direction. It already quietly feeds the CSP scanner's ranking and the LEAP scanner's hard filter — not purely cosmetic. This backtest reimplements that exact model verbatim (same features, same hyperparameters, same 0.55/0.45 thresholds) against 2.5 years of real Alpaca 5-min bars, testing both the as-deployed shared-model design and a fixed per-ticker version, across 3 training-window sizes.

"Pre-cost edge" = avg return + the 6bps round-trip cost assumption — i.e. what the edge would be if trading were free. All six land under +0.005%, statistically indistinguishable from zero across tens of thousands of trades each. Every configuration's win rate sits 14-20 points below Day Trader's already-live, already-validated strategy — this isn't "worse," it's a different sign entirely.

What the parameter grid resolved

Question going inWhat the data actually shows
Does more training data help?Barely. 60-day windows (11,000+ rows) are marginally less bad than 5-day windows (matching what's live today), but walk-forward CV accuracy sat in a 0.48-0.53 band at every single retrain point, regardless of window size, across the whole 2.5-year run. The model isn't starved for data — there's close to nothing in these 9 features that predicts next-5-min-bar direction at any size tested.
Is the shared-model architecture the problem?No. Going in, "one classifier reused across all 4 tickers" looked like an obvious flaw. Fixing it (independent per-ticker models) doesn't rescue the strategy — results are statistically indistinguishable from the shared-model runs, sometimes marginally worse. There was no edge for the architecture to be losing.
Does it work in some regime?No. Split on SPY's own rolling realized volatility, both HIGH_VOL and LOW_VOL periods are negative in every configuration.
Any ticker where it works?No — SPY is consistently the worst (18-25% win rate), the other three cluster in the low-to-mid 30s. Consistent with SPY being the most efficiently-priced instrument tested, leaving least room for a generic technical classifier.

A real bug caught along the way

The first full run used Alpaca's default unadjusted prices and produced a phantom +90% single-trade "return" on NVDA — priced straight across NVDA's real 2024-06-07 10-for-1 stock split (~$1208 pre-split vs. ~$120 post-split, same underlying value, zero real return). Caught by inspecting the actual trade record rather than trusting the summary number, fixed by requesting split+dividend-adjusted prices, and the entire grid was re-run from scratch. The conclusion didn't change; the corrected numbers are what's reported here.

Honest scope

This tests one specific thing: these 9 features, this model class/hyperparameters, next-5-min-bar direction as the target, and a reversal-on-opposite-signal trade rule — not whether any signal could ever be built from similar data. A materially different feature set, prediction horizon, or model architecture would be a new research question. Phase B (live execution) is not being started — it was explicitly gated on this result, and a negative result is being reported as one rather than as a prompt to tune parameters until something looks better.
